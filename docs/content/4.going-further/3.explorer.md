The Nuxt Shopify module mounts a GraphQL explorer for each API client that
you can access in development mode to explore and test your GraphQL queries.

When starting the Nuxt development server you can then access each explorer in your browser:

* `/_explorer/storefront`
* `/_explorer/customer-account`
* `/_explorer/admin/<token>`

The storefront and customer account explorers send their queries through the same routes as your app:

* The storefront explorer uses the [Storefront API proxy](/essentials/storefront#the-storefront-api-proxy), with the
  `publicAccessToken` of the storefront client if it has one.
* The customer account explorer uses the
  [customer account proxy](/essentials/customer-account#the-customer-account-proxy), so it is only available if `proxy`
  is enabled. Its queries run as the logged in customer, so log in on the same domain first, otherwise they fail with
  a `401` error.
* The admin explorer has its own proxy, which adds your Admin API credentials. The `<token>` in its URL changes every
  time the dev server starts, so open it from the link in the output of the dev server.

::note
Explorers are only registered in dev mode, and they only answer requests from your own machine on `localhost`,
`127.0.0.1`, `[::1]` or `local.tryhydrogen.dev`, the domain of the
[local customer account setup](/essentials/customer-account#local-development).
Requests through a tunnel or from your local network are refused, because the explorers run queries with your credentials.
::

By default, each client mounts an explorer when running in dev mode.
You can customize this behavior by setting the `explorer` option in the client config:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    clients: {
      storefront: {
        explorer: true,
      },
      customerAccount: {
        explorer: false,
      },
      admin: {
        explorer: true,
      },
    },
  },
})
```

::note
The explorer UI is currently rendered by [graphql-yoga](https://the-guild.dev/graphql/yoga-server). The `explorer`
option describes the capability rather than the renderer, so swapping it out later will not change your config.
::
