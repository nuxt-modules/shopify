The Nuxt Shopify module provides built-in error handling for the Storefront, Customer Account and Admin API clients.

## Error Configuration

By default, the module will throw an error if something within a Storefront, Customer Account or Admin API client request fails instead of catching and returning an `errors` object.
This is done so that Nuxt can take over the error handling when using a client within Nitro or with useAsyncData.

You can customize this behavior by setting the `errors.throw` option in the module config:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    errors: {
      throw: true,
    },
  },
})
```

Setting this to false will prevent clients from throwing an error when a request fails and instead return an `errors` object with the response:

::tabs
  :::tabs-item{label="throw: true"}
  ```vue [app/pages/product.vue]
  <script setup lang="ts">
  const id = 'invalid-id'

  const { data, error } = await useStorefrontData(`product-${id}`, `#graphql
    query GetProduct($id: ID!) {
      product(id: $id) {
        id
        title
      }
    }
  `, { 
    variables: { id },
  })

  if (error.value) {
    // Error caught by Nuxt, immediate access through useAsyncData
    console.error(error.value)
  }
  </script>
  ```
  :::

  :::tabs-item{label="throw: false"}
  ```vue [app/pages/product.vue]
  <script setup lang="ts">
  const id = 'invalid-id'

  const { data, errors } = await useStorefront().request(`#graphql
    query GetProduct($id: ID!) {
      product(id: $id) {
        id
        title
      }
    }
  `, {
    variables: { id },
  })

  if (errors) {
    // Response contains errors when not throwing
    console.error(errors)
  }
  </script>
  ```

  Note that `useStorefrontData` unwraps the response and only returns its `data`, dropping the `errors` object.
  With `throw: false`, use the raw client as shown above or the `shopify:storefront:client:errors` hook to observe errors.
  :::
::

The thrown error doesn't show Shopify's response to your visitors.
Its message is always `[shopify] Request to Shopify failed`.
Its status is the status that Shopify sent, or `502` if the response has GraphQL errors but a successful status.
For requests on the server, Shopify's errors are written to the server log.
In your own code, you can read them from the error's `cause`, such as the GraphQL errors in `cause.graphQLErrors`.
The `cause` is never included in error pages, JSON error responses or the page payload.

On the server, requests to Shopify time out after 30 seconds, the same as in Hydrogen.
With `retries`, each attempt gets another 30 seconds.
A request that times out fails the same way as a request that Shopify didn't answer.
In the browser, the browser's own timeouts apply.

::note
Authentication errors also follow the `errors.throw` option.
A `useCustomerAccount` request fails with a `401` error if the customer is not logged in.
A `useAdmin` request fails with a `502` error if the client can't get an access token.
Shopify's response to the failed token request is only written to the server log.
With `throw: false`, these errors are returned in the response's `errors`, with the status in `networkStatusCode`.
::

## Handling Errors

When `errors.throw` is set to true (default), Nuxt and Nitro can handle errors automatically.
For example, when a client throws an error within a Nitro endpoint, Nitro will catch it and return an error response with its status and the generic message.
Shopify's errors are written to the server log.

```ts [server/api/product/[id].ts]
export default defineEventHandler((event) => {
  const id = 'invalid-id'

  const storefront = useStorefront(event)

  // This will throw an error that will be returned as a response with the generic message,
  // and the server log shows: [shopify] GraphQL error: Variable $id of type ID! was provided invalid value
  return storefront.request(`#graphql
    query GetProduct($id: ID!) {
      product(id: $id) {
        id
        title
      }
    }
  `, { 
    variables: { id }
  })
})
```

The module also provides hooks to log errors or notify an external service when a client request fails:

::code-group
```ts [app/plugins/errors.ts]
export default defineNuxtPlugin({
  setup: (nuxtApp) => {
    nuxtApp.hooks.hook('shopify:storefront:client:errors', ({ errors }) => {
      console.error('[shopify] storefront client received errors', errors)
    })

    nuxtApp.hooks.hook('shopify:customer-account:client:errors', ({ errors }) => {
      console.error('[shopify] customer account client received errors', errors)
    })
  }
})
```

```ts [server/plugins/errors.ts]
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('shopify:storefront:client:errors', ({ errors }) => {
    console.error('[shopify] storefront client received errors', errors)
  })

  nitroApp.hooks.hook('shopify:customer-account:client:errors', ({ errors }) => {
    console.error('[shopify] customer account client received errors', errors)
  })

  nitroApp.hooks.hook('shopify:admin:client:errors', ({ errors }) => {
    console.error('[shopify] admin client received errors', errors)
  })
})
```
