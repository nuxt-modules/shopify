The Storefront API is a public API that allows you to access your Shopify store's data, such as products, collections, and customer information.
It is designed to be used in client-side applications, such as a Nuxt frontend.
To use the Storefront API, you need to obtain a public or private access token.

::note
See the [module configuration](/essentials/configuration) to see how to set up the module for the Storefront API.
If you need help obtaining your access tokens, see the [Shopify Setup Guide](/essentials/setup-shopify).
::

## Usage

Once configured, you can use the Storefront API in your Nuxt application via the `useStorefront` and `useStorefrontData` composables.
You can use `useStorefront` both in your app and in server routes.
`useStorefrontData` wraps it in Nuxt's `useAsyncData` to fetch data in pages and components.

### Client-side

#### useStorefront

When setting the `publicAccessToken` for the storefront client in the module configuration, you can use the `useStorefront` composable
in your client-side code. For example, in a page component:

```vue [app/pages/product.vue]
<script setup lang="ts">
const storefront = useStorefront()

const { data } = await storefront.request(`#graphql
  query GetProduct($handle: String!) {
    product(handle: $handle) {
      id
      title
      description
    }
  }
`, {
  variables: {
    handle: 'high-top-sneakers',
  }
})
</script>

<template>
  <div v-if="data">
    <h1>{{ data.product.title }}</h1>

    <p>{{ data.product.description }}</p>
  </div>
</template>
```

You can also wrap the `useStorefront` composable in another composable, to build an abstracted data fetching method:

```ts [app/composables/useProduct.ts]
export const useProduct = (handle: string) => {
  const storefront = useStorefront()

  return storefront.request(`#graphql
    query GetProduct($handle: String!) {
      product(handle: $handle) {  
        id
        title
        description
      }
    }
  `, {
    variables: {
      handle,
    }
  })
}
```

This way, you can reuse the `useProduct` composable in multiple places in your application.

#### The Storefront API proxy

By default, requests from the browser are sent to a proxy on your own domain at `/api/<version>/graphql.json`, which forwards them to your store.
The proxy is provided by Hydrogen.
Requests without an access token are sent with the `publicAccessToken` of the storefront client.

The proxy only forwards the headers that the Storefront API needs.
Custom headers that you add in the browser, through the `headers` option or the [`shopify:storefront:client:configure` hook](/going-further/hooks), are not sent to Shopify.
Shopify's session cookies are only set in the browser if the visitor's consent allows them.

To send requests from the browser directly to Shopify, set `proxy: false` in the storefront client config.
Statically generated sites always do this, because there is no server to run the proxy.
The proxy doesn't cache responses, see [caching](/essentials/caching) to cache requests during server-side rendering.

#### useStorefrontData

You can wrap the `useStorefront` call with Nuxt's `useAsyncData` composable to integrate into the hybrid rendering model.
To shorten the syntax, the module provides a composable called `useStorefrontData` that automatically does this for us:

```vue [app/pages/product.vue]
<script setup lang="ts">
const handle = 'high-top-sneakers'

const { data } = await useStorefrontData(`product-${handle}`, `#graphql
  query GetProduct($handle: String!) {
    product(handle: $handle) {
      id
      title
      description
    }
  }
`, {
  variables: {
    handle,
  }
})
</script> 

<template>
  <div v-if="data">
    <h1>{{ data.product.title }}</h1>

    <p>{{ data.product.description }}</p>
  </div>
</template>
```

Standard features of `useAsyncData` such as caching, revalidation, and error handling are all available when using `useStorefrontData`.
You can also use `transform`, `pick`, and other options to further customize the behavior of the data fetching.

### Server-side

#### useStorefront

When setting either the `publicAccessToken` or `privateAccessToken` for the storefront client in the module configuration,
you can use the `useStorefront` composable in your server-side code. 
For example, in a server route:

```ts [server/api/product/[handle].ts]
export default defineEventHandler((event) => {
  const handle = getRouterParam(event, 'handle')!

  const storefront = useStorefront(event)

  return storefront.request(`#graphql
    query GetProduct($handle: String!) {
      product(handle: $handle) {
        id
        title
        description
      }
    }
  `, {
    variables: {
      handle,
    }
  })
})
```

::note
Passing the `event` is optional, but recommended.
With the event, the client uses the runtime config of the current request, including environment variables set at runtime, and forwards Shopify's cookies from the incoming request.
Without the event, the client uses the config from build time.

When using a `privateAccessToken` and passing the event, the IP address of the buyer is sent through the `Shopify-Storefront-Buyer-IP` header, which Shopify uses to apply its rate limits per buyer instead of per server.
The address is read from the header that your hosting platform sets, see the [`buyerIpHeader`](/essentials/configuration#storefront-client) option.
By default, `X-Forwarded-For` is not used, because the browser can send any value in it.
To send another address, or none, create the client yourself with `createStorefrontApiClient` and set its `buyerIp` option to the address or to `false`.
::

### Using validation

Using Nitro's built-in input validation, you can match the variables of your GraphQL queries before sending them to the
API.

For this example we'll use the Zod library, but you can use any validation library you like.

First, install the validation library:

```bash
npm install zod
```

Then, import it and create a schema:

```ts
import { z } from 'zod'

const schema = z.object({
  first: z.coerce.number().min(1),
})
```

::note
`z.coerce.number()` converts the string value of the `first` variable to a number and then matches it against the
Zod schema. In Nitro, the query variables are always strings, so we convert to a number here before we
pass it to the API.
::

Next, we can use Nitro's built-in `getValidatedQuery` utility to validate the query variables:

```ts [server/api/products.ts]
import { z } from 'zod'

const schema = z.object({
  first: z.coerce.number().min(1),
})

export default defineEventHandler(async (event) => {
  const variables = await getValidatedQuery(event, schema.parse)

  const storefront = useStorefront(event)

  const query = `#graphql
    query FetchProducts($first: Int) {
      products(first: $first) {
        nodes {
          id
          title
          description
        }
      }
    }
  `

  return storefront.request(query, { variables })
})
```

Now we can call the API at `/api/products` with the following variables:

```ts [app/pages/your-page.vue]
// Requests /api/products?first=1
const response = await useFetch('/api/products', {
    query: {
        first: 1,
    },
})
```

With the validation, requests will fail before reaching Shopify if the variable `first` is not a number.

## Shopify Routes

When the storefront client is configured or analytics is enabled, the module adds the routes that Shopify expects every Hydrogen storefront to have.
They are matched before your own routes:

- `/api/<version>/graphql.json`: the [Storefront API proxy](#the-storefront-api-proxy), used by the browser client and Shopify's scripts
- `/api/cart`: the [cart](#cart) API
- `/api/predictive-search`: the [predictive search](#predictive-search) API
- `/checkout`: redirects to the checkout of the visitor's cart, or to the home page if there is no cart
- `/cart/<variant>:<quantity>` and `/buy/<item>:<quantity>`: cart and buy permalinks, such as the checkout links you create in your Shopify admin
- `/cart.js` and `/cart/{add,update,change,clear}`, also with `.js` or `.json` and behind a locale prefix such as `/de-de`: the AJAX cart API used by Shopify's scripts
- `POST /__shopify/api/collect`: Shopify's performance beacon
- `/.well-known/ucp`: your store's UCP business profile
- `/api/mcp` and `/api/ucp/mcp`: the MCP endpoints for AI agents
- `/.well-known/apple-developer-merchantid-domain-association`: the domain verification for Apple Pay
- `/.well-known/shopify/fec/produce`: Shopify's event collector

Only Shopify's own cookies (`_shopify_*`, `_tracking_consent` and `cart`) are forwarded to Shopify.
Requests without an access token are sent with the `publicAccessToken` of the storefront client, so the proxy, the cart API and the checkout also work while your store is password protected.
The AJAX cart and `/api/mcp` don't use an access token, so they don't work while your store is password protected.

Hydrogen uses its own Storefront API client for these routes.
With a `privateAccessToken`, it uses the private token and sends the buyer's IP address, the same way as [`useStorefront` on the server](#server-side).
Without one, it uses the `publicAccessToken`.
This means the cart, the checkout and the redirects also work if you only set a `privateAccessToken`.
The Storefront API proxy is the exception, it never uses the `privateAccessToken`.
If you set a [`storefrontId`](/essentials/configuration#basic-options), the routes send it to Shopify in the `Shopify-Storefront-Id` header, whether or not analytics is enabled.

The routes use the [market](#markets) of the request.
They are never cached, even if one of your `routeRules` matches them, see [caching](/essentials/caching#configuration).

::warning
These routes need a server.
On a statically generated site, they only work if your host forwards them to your store.

The routes are always served from the root of your domain.
For this reason, the storefront client, the customer account client and analytics don't support an `app.baseURL` other than `/`.
The module shows a warning when Nuxt starts if you set one.
::

### Route templates

Shopify's emails, product feeds and scripts link to your pages at Shopify's standard paths, such as `/products/<handle>`.
If your app uses the standard paths, you don't need to configure anything: `/products`, `/collections`, `/pages`, `/policies`, `/blogs`, `/cart` and `/search`.
Hydrogen's starter apps and the starter template use them.
They only set `productInCollection: '/products/:productHandle'`, which redirects links like `/collections/<collection>/products/<product>` to the product page.

If your app uses other paths, set them in the `routeTemplates` option, in Hydrogen's format:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    routeTemplates: {
      product: '/product/:productHandle',
      collection: '/collection/:collectionHandle',
      article: '/blog/:blogHandle/:articleHandle',
    },
  },
})
```

Only set the keys of the pages that don't use the standard path.
The available keys are `product`, `productInCollection`, `collection`, `collectionList`, `page`, `policy`, `blog`, `article`, `cart` and `search`.
Leave out the locale prefix, Hydrogen adds the `pathPrefix` of the request's [market](#markets).

Shopify's scripts use the route templates to link to your pages and to report the type of each page that is viewed, such as `product`.
The [variant links](#variant-links) and [redirects](#redirects) below use them as well.

### Variant links

Shopify's emails and product feeds link to a product variant with a `variant` query parameter, such as `/products/shirt?variant=1234`.
The module redirects these links to the selected options of the variant, such as `/products/shirt?Color=Red&Size=M`.
Your product page then reads the selected options from the query, as shown in the [product page example](/examples/product-page).

### Redirects

When a page is not found during server-side rendering, the module checks for a redirect before your error page is rendered:

- `/admin` redirects to your store's admin
- Shopify's standard paths redirect to your route templates, for example `/products/shirt` to `/product/shirt`
- a `return_to` or `redirect` query parameter is followed if it points to your own site
- the URL redirects from your Shopify admin are followed

Checking the URL redirects from your Shopify admin needs one Storefront API request for each page that is not found.

## Cart

When the storefront client is configured, the module adds Hydrogen's cart API at `/api/cart`, so you don't need any server code for the cart.
In your app, create the cart components with `createCartComponents` from `@shopify/hydrogen/vue`:

```ts [app/utils/cart.ts]
import type { CartServerHandlers } from '@shopify/hydrogen'

import { createCartComponents } from '@shopify/hydrogen/vue'

export const { CartProvider, useCart, useCartForm } = createCartComponents<CartServerHandlers>()
```

Then wrap your app in `CartProvider`, and use `useCart` to read the cart and `useCartForm` to change it.
See [Using the Cart](/examples/cart) for a complete example with an add to cart button and a cart drawer.

To add fields such as metafields to the cart, set a cart fragment in the [`cart`](/essentials/configuration#basic-options) option.
When the customer account client is configured, logging in links the cart to the customer, see [customer account](/essentials/customer-account#the-cart).

The cart API only accepts changes that are sent from your storefront, so other websites can't change a visitor's cart, for example by submitting a form to `/api/cart`.
The same applies to AJAX cart requests sent with `POST`, such as `/cart/add.js`.

## Markets

The [Shopify routes](#shopify-routes), including the cart, and the customer account login use the market of the request.
Shopify's [scripts](/essentials/analytics#buyer-market) also use it for the events they send.
If your app doesn't set a market, the module uses the [`defaultMarket`](/essentials/configuration#basic-options) option.
If that is not set either, it uses your shop's default market, which it fetches once with the storefront client.

Without the storefront client, for example if you only use the customer account client or analytics, the module can't fetch your shop's default market and shows a warning when Nuxt starts.
In this case, set `defaultMarket` or the market of each request, otherwise the module's routes fail with a `502` error.

If your storefront has multiple markets, set the market of each request in a Nitro plugin.
Pages have the market in their locale prefix, and pages without a prefix use your default market.
The cart API and the customer account login route have no prefix, so read their market from a cookie instead, such as the locale cookie of `@nuxtjs/i18n` (`detectBrowserLanguage.useCookie`, enabled by default):

```ts [server/plugins/market.ts]
import type { ShopifyScriptsI18n } from '@shopify/hydrogen'

import { CUSTOMER_ACCOUNT_LOGIN_PATH } from '@shopify/hydrogen/customer-account'

const LOCALE = /^([a-z]{2})-([a-z]{2})$/i

export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('request', (event) => {
    const { pathname } = getRequestURL(event)

    const [, segment] = pathname.split('/')

    const prefixed = segment !== 'api' && pathname !== CUSTOMER_ACCOUNT_LOGIN_PATH

    const locale = prefixed ? segment : getCookie(event, 'i18n_redirected')

    const [, language, country] = LOCALE.exec(locale ?? '') ?? []

    if (!language || !country) return

    event.context.shopifyMarket = {
      language: language.toUpperCase(),
      country: country.toUpperCase(),
      pathPrefix: prefixed ? `/${segment}` : undefined,
    } as ShopifyScriptsI18n
  })
})
```

Set `pathPrefix` to the locale prefix of the page, so that Hydrogen's [redirects](#redirects) and the links of Shopify's scripts keep it.
If you know the currency of the market, set `currency` too.
Otherwise, when analytics is enabled, the module fetches the currency once per market for Shopify's scripts.

Set the market in the `request` hook as shown above, so it is set before any route handler runs.
The module creates Hydrogen's request context once per request, with the market that is set at that time, and ignores later changes to `shopifyMarket`.
The request context is available as `event.context.shopifyRequestContext`, typed as Hydrogen's `ShopifyRequestContext`.

The market of the request is not applied to your own queries.
To localize them, pass the country and language as `@inContext` variables, as in the [collection page example](/examples/collection-page).
A cart keeps the currency of the market it was created in.
When a visitor switches to another country, update the buyer identity of the cart with `cartBuyerIdentityUpdate`, as the starter template does.

## Predictive search

When the storefront client is configured, the module also adds Hydrogen's predictive search API at `GET /api/predictive-search`.
It uses the same Storefront API client as the cart.
You can set its defaults in the [`predictiveSearch`](/essentials/configuration#basic-options) option, such as the result `limit`, the `types` to search for and `fragments` to add fields to the results.

In your app, wrap your search in `PredictiveSearchProvider` from `@shopify/hydrogen/vue`:

```vue [app/components/PredictiveSearch.vue]
<script setup lang="ts">
import { PredictiveSearchProvider } from '@shopify/hydrogen/vue'
</script>

<template>
  <PredictiveSearchProvider :limit="5">
    <SearchForm />
  </PredictiveSearchProvider>
</template>
```

Inside the provider, `usePredictiveSearchForm` binds your search form and `usePredictiveSearch` reads the results:

```vue [app/components/SearchForm.vue]
<script setup lang="ts">
import { getPredictiveSearchItemUrl } from '@shopify/hydrogen'
import { usePredictiveSearch, usePredictiveSearchForm } from '@shopify/hydrogen/vue'

const routes = useRuntimeConfig().public._shopify?.routeTemplates ?? {}

const { formProps, register } = usePredictiveSearchForm()

const result = usePredictiveSearch(state => state.result)
</script>

<template>
  <form v-bind="formProps()">
    <input
      v-bind="register('query')"
      placeholder="Search"
    >
  </form>

  <ul v-if="result.total">
    <li
      v-for="product in result.items.products"
      :key="product.id"
    >
      <NuxtLink :to="getPredictiveSearchItemUrl(product, { routes, term: result.term })">
        {{ product.title }}
      </NuxtLink>
    </li>
  </ul>
</template>
```

The input searches while the visitor types.
Without JavaScript, the form submits to your search page at `/search?q=<term>`.
`getPredictiveSearchItemUrl` links each result to its page and adds Shopify's search tracking parameters.
To search or clear the results from your own code instead, use `usePredictiveSearchActions`.

If your search opens in a modal, make the search button a link to `/search` and open the modal in its click handler.
This way, the button also works before JavaScript has loaded.
The search page of the starter template filters and sorts its results with `CollectionProvider` from `@shopify/hydrogen/vue`, like its collection pages.
