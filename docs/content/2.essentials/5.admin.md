The Admin API is a private API that allows you to manage your Shopify store's data, such as orders, customers, products, and inventory.
It is designed to be used in server-side applications only, as it requires credentials that should never be exposed to the client.

::note
See the [module configuration](/essentials/configuration) to see how to set up the module for the Admin API.
If you need help obtaining your credentials, see the [Shopify Setup Guide](/essentials/setup-shopify).
::

## Authentication

The module supports multiple authentication methods for the Admin API:

::tabs
  :::tabs-item{label="Client Credentials"}
    The recommended method for apps created via the [Shopify Dev Dashboard](https://dev.shopify.com/dashboard).
    The module automatically obtains and refreshes access tokens using your client ID and secret.

    ```ts [nuxt.config.ts]
    export default defineNuxtConfig({
      shopify: {
        name: "nuxt-module-store",
        clients: {
          admin: {
            apiVersion: "2026-10",
            clientId: "...",
            clientSecret: "...",
          },
        },
      },
    })
    ```

    Access tokens are valid for 24 hours and are automatically refreshed before expiry.
  :::

  :::tabs-item{label="Static Access Token"}
    For legacy custom apps created in the Shopify Admin that provide a permanent access token.

    ```ts [nuxt.config.ts]
    export default defineNuxtConfig({
      shopify: {
        name: "nuxt-module-store",
        clients: {
          admin: {
            apiVersion: "2026-10",
            accessToken: "...",
          },
        },
      },
    })
    ```

    ::::warning
    As of January 1, 2026, you can no longer create new legacy custom apps in the Shopify Admin.
    Use client credentials for new apps.
    ::::
  :::

  :::tabs-item{label="Offline Token with Refresh"}
    For apps that have pre-obtained an offline access token with a refresh token.

    ```ts [nuxt.config.ts]
    export default defineNuxtConfig({
      shopify: {
        name: "nuxt-module-store",
        clients: {
          admin: {
            apiVersion: "2026-10",
            clientId: "...",
            clientSecret: "...",
            accessToken: "...",
            refreshToken: "...",
          },
        },
      },
    })
    ```
  :::
::

### Token Storage

When using client credentials or refresh tokens, the module stores obtained tokens using [Unstorage](https://github.com/unjs/unstorage).
By default, tokens are stored in memory. You can configure a persistent storage driver:

::tabs
  :::tabs-item{label="Custom Mount Name"}
    ```ts [nuxt.config.ts]
    export default defineNuxtConfig({
      shopify: {
        clients: {
          admin: {
            // Use a custom storage mount name
            tokenStorage: "my-token-store",
          },
        },
      },

      nitro: {
        storage: {
          "my-token-store": {
            driver: "redis",
            host: "localhost",
            port: 6379,
          },
        },
      },
    })
    ```
  :::

  :::tabs-item{label="Driver Config"}
    ```ts [nuxt.config.ts]
    export default defineNuxtConfig({
      shopify: {
        clients: {
          admin: {
            // Configure a driver directly
            tokenStorage: {
              driver: "redis",
              host: "localhost",
              port: 6379,
            },
          },
        },
      },
    })
    ```
  :::
::

## Usage

Once configured, you can use the Admin API in your Nuxt application via the `useAdmin` composable.
This composable can only be used on the server-side (in server routes, middleware, or server-only composables).
Put your Admin API operations in an `admin` directory or in files named `admin.ts` or ending in `.admin.ts`, so that [code generation](/going-further/codegen#routing-operations-to-the-right-api) uses the Admin API schema for them.

### Server-side

#### useAdmin

```ts [server/api/admin/orders.ts]
export default defineEventHandler(async (event) => {
  const admin = useAdmin(event)

  return admin.request(`#graphql
    query GetOrders($first: Int!) {
      orders(first: $first) {
        edges {
          node {
            id
            name
            totalPriceSet {
              shopMoney {
                amount
                currencyCode
              }
            }
            createdAt
          }
        }
      }
    }
  `, {
    variables: {
      first: 10,
    },
  })
})
```

::note
Passing the `event` is optional, but recommended.
With the event, the client uses the runtime config of the current request, including environment variables set at runtime.
::

You can also wrap the `useAdmin` composable in another composable to build an abstracted data fetching method:

```ts [server/utils/admin.ts]
import type { H3Event } from 'h3'

export const useOrder = async (event: H3Event, id: string) => {
  const admin = useAdmin(event)

  return admin.request(`#graphql
    query GetOrder($id: ID!) {
      order(id: $id) {
        id
        name
        totalPriceSet {
          shopMoney {
            amount
            currencyCode
          }
        }
        lineItems(first: 10) {
          edges {
            node {
              title
              quantity
            }
          }
        }
      }
    }
  `, {
    variables: {
      id,
    },
  })
}
```

### Using validation

Using Nitro's built-in input validation, you can match the variables of your GraphQL queries before sending them to the
API.

For this example we'll use the Zod library, but you can use any validation library you like.

First, install the validation library:

```bash
npm install zod
```

Then, import it and create a schema:

```ts
import { z } from "zod"

const schema = z.object({
  first: z.preprocess(v => Number(v), z.number().min(1).max(250)),
  status: z.enum(["status:open", "status:closed", "status:cancelled"]).optional(),
})
```

Next, we can use Nitro's built-in `getValidatedQuery` utility to validate the query variables:

```ts [server/api/admin/orders.ts]
import { z } from "zod"

const schema = z.object({
  first: z.preprocess(v => Number(v), z.number().min(1).max(250)),
  status: z.enum(["status:open", "status:closed", "status:cancelled"]).optional(),
})

export default defineEventHandler(async (event) => {
  const admin = useAdmin(event)
  const variables = await getValidatedQuery(event, schema.parse)

  const query = `#graphql
    query FetchOrders($first: Int!, $status: String) {
      orders(first: $first, query: $status) {
        edges {
          node {
            id
            name
            totalPriceSet {
              shopMoney {
                amount
                currencyCode
              }
            }
            displayFinancialStatus
            displayFulfillmentStatus
          }
        }
      }
    }
  `

  return admin.request(query, { variables })
})
```

Now we can call the API at `/api/admin/orders` with the following variables:

```ts [app/pages/admin/orders.vue]
const { data: orders } = await useFetch("/api/admin/orders", {
  query: {
    first: 50,
    status: "status:open",
  },
})
```

Now the request will fail before reaching Shopify if the variables don't match the schema.
