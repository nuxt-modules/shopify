The Nuxt Shopify module can be configured via the `shopify` property in your `nuxt.config.ts` file.

The module validates the configuration when Nuxt starts.
Unknown options, such as a misspelled key or an option from version 1, are ignored with a warning.
Private options in `runtimeConfig.public.shopify` also show a warning, because Nuxt sends this object to the browser.

If the options of a feature are invalid, such as those of a client, `webhooks` or `analytics`, `nuxt dev` and `nuxt prepare` log the error and set up the module without that feature.
An invalid `name` disables the whole module.
`nuxt build` fails instead.
See the [migration guide](/getting-started/migration) for the options that changed in version 2.

## Environment variables

Any option can be supplied through the environment instead of being written into `nuxt.config.ts`, which is
how you keep tokens out of the repository. Nuxt only maps an environment variable onto a config key that
**already exists**, so declare the key first, in `shopify` or `runtimeConfig.shopify`:

::card
  :::tabs
    ::::tabs-item{label="Module Config"}
    ```ts [nuxt.config.ts]
    export default defineNuxtConfig({
      modules: ["@nuxtjs/shopify"],

      shopify: {
        name: "nuxt-module-store",

        clients: {
          storefront: {
            apiVersion: "2026-10",
            publicAccessToken: "...",
          },
        },
      },
    })
    ```
    ::::

    ::::tabs-item{label="Runtime Config"}
    ```ts [nuxt.config.ts]
    export default defineNuxtConfig({
      modules: ["@nuxtjs/shopify"],

      runtimeConfig: {
        shopify: {
          name: "nuxt-module-store",

          clients: {
            storefront: {
              apiVersion: "2026-10",
              publicAccessToken: "...",
            },
          },
        },

        public: {
          shopify: {
            clients: {
              storefront: {
                // Override the public storefront token
                publicAccessToken: "...",
              },
            },
          },
        },
      },
    })
    ```
    ::::
  :::
::

```sh [.env]
NUXT_SHOPIFY_NAME="nuxt-module-store"
NUXT_SHOPIFY_CLIENTS_STOREFRONT_API_VERSION="2026-10"
NUXT_SHOPIFY_CLIENTS_STOREFRONT_PUBLIC_ACCESS_TOKEN="..."
```

Precedence, highest first: `runtimeConfig.public.shopify`, then `runtimeConfig.shopify`, then the `shopify`
block in `nuxt.config.ts`.

The server validates the environment variables again when it starts.
If a value is invalid, the feature it belongs to, such as `clients.customerAccount`, uses its configuration from the build and shows a warning.
If the `name` is invalid, the whole configuration from the build is used.

Environment variables that are set during the build are included in the server bundle, because [server clients without the event](/essentials/storefront#server-side) use the configuration from the build.
The customer account session password is the exception.
It is never included in a production build, so set `NUXT_SHOPIFY_CLIENTS_CUSTOMER_ACCOUNT_SESSION_PASSWORD` where your app runs.

## Resolved config

The module parses and resolves your configuration on startup and writes the result back to the runtime
config. You can read it from `_shopify`:

- `useRuntimeConfig()._shopify`: Full resolved config on the server, typed as `ShopifyConfig`. It
  carries credentials, so it must never reach the browser.
- `useRuntimeConfig().public._shopify`: Filtered copy that is safe in the browser, typed as
  `PublicShopifyConfig`.
- `useRuntimeConfig().shopify`: Config input, with the `NUXT_SHOPIFY_*` environment variables applied. Resolved
  into `_shopify` when the server starts.

## Quickstart

Minimal configuration to get started:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ["@nuxtjs/shopify"],

  shopify: {
    name: "nuxt-module-store",
    clients: {
      storefront: {
        apiVersion: "2026-10",
        publicAccessToken: "...",
      },

      customerAccount: {
        apiVersion: "2026-10",
        clientId: "...",
      },

      admin: {
        apiVersion: "2026-10",
        clientId: "...",
        clientSecret: "...",
      },
    },
  },
})
```

::note
See the [Shopify Setup Guide](/essentials/setup-shopify) to learn how to find your store name and access tokens.
::

## Full Configuration Reference

### Basic Options

::field-group
  :::field{name="name" type="string" required}
  Your Shopify store name (e.g., `nuxt-module-store`).
  :::

  :::field{name="origin" type="string"}
  Public URL of your app (e.g., `https://shop.example.com`). Set it if your app runs behind a reverse proxy that changes
  the `Host` header or doesn't send `X-Forwarded-Proto: https`, so that redirects and requests to Shopify use your public
  URL - default: the origin of the request, server-side only. Environment variable: `NUXT_SHOPIFY_ORIGIN`, with the key
  declared as `origin: ''`
  :::

  :::field{name="shopId" type="string | number"}
  Numeric ID of your shop (e.g., `12345`, not `gid://shopify/Shop/12345`), used for
  [customer accounts](/essentials/customer-account) and [analytics](/essentials/analytics) - default: fetched from your
  store. Environment variable: `NUXT_SHOPIFY_SHOP_ID`, with the key declared as `shopId: ''`
  :::

  :::field{name="storefrontId" type="string | number"}
  Storefront ID of your Hydrogen sales channel. Attributes your analytics to the Hydrogen channel instead of the Headless
  channel. It is sent with server-side Storefront API requests, whether or not analytics is enabled. Environment variable:
  `NUXT_SHOPIFY_STOREFRONT_ID`, with the key declared as `storefrontId: ''`
  :::

  :::field{name="defaultMarket" type="object"}
  The [market](/essentials/storefront#markets) of requests that don't set `event.context.shopifyMarket` - default: your
  shop's default market, fetched with the storefront client. If you don't use the storefront client, you need to set it.
  Environment variables: `NUXT_SHOPIFY_DEFAULT_MARKET_COUNTRY`, `NUXT_SHOPIFY_DEFAULT_MARKET_LANGUAGE` and
  `NUXT_SHOPIFY_DEFAULT_MARKET_CURRENCY`, with the keys declared as
  `defaultMarket: { country: '', language: '', currency: '' }`. Empty values count as not set
  :::

  :::field{name="defaultMarket.country" type="string" required}
  Country code of the market (e.g., `US`)
  :::

  :::field{name="defaultMarket.language" type="string" required}
  Language code of the market (e.g., `EN`)
  :::

  :::field{name="defaultMarket.currency" type="string"}
  Currency code of the market (e.g., `USD`), used by Shopify's scripts - default: fetched with the storefront client
  when analytics is enabled
  :::

  :::field{name="routeTemplates" type="object"}
  Paths of your pages that don't use Shopify's standard paths, such as `{ product: '/product/:productHandle' }`. See
  [route templates](/essentials/storefront#route-templates)
  :::

  :::field{name="cart" type="object"}
  Options for the [cart](/essentials/storefront#cart) API at `/api/cart`. Set `fragment` to a `CartFragment` fragment on
  `Cart`, created with `gql` from `@shopify/hydrogen`, to add fields such as metafields to the cart
  :::

  :::field{name="predictiveSearch" type="object"}
  Options for the [predictive search](/essentials/storefront#predictive-search) API at `/api/predictive-search`:
  `fragments`, `limit`, `limitScope`, `types`, `searchableFields` and `unavailableProducts`, as in Hydrogen's
  `createPredictiveSearchServerHandlers`
  :::

  :::field{name="logger" type="object"}
  Optional module logger configuration ([Consola](https://github.com/unjs/consola) options). Hydrogen's logs use it as
  well, tagged `shopify:hydrogen`
  :::
::

### Client Configuration

Configure one or more API clients:

#### API versions

Shopify ships a new API version every quarter and supports each one for at least a year. Every client takes an
`apiVersion`.
By default, the clients use the API version of the installed `@shopify/hydrogen`, such as `2026-10` for Hydrogen 2026.10.
This way, the API version only changes when you upgrade Hydrogen.
Set `apiVersion` per client to use another version:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    name: 'nuxt-module-store',

    clients: {
      storefront: {
        apiVersion: '2026-10',
        publicAccessToken: '...',
      },
    },
  },
})
```

#### Storefront Client

::field-group
  :::field{name="apiVersion" type="string"}
  Shopify [API version](https://shopify.dev/docs/api/usage/versioning) to use (e.g., `2026-10`) - default: the API
  version of the installed `@shopify/hydrogen`
  :::

  :::field{name="publicAccessToken" type="string"}
  Public access token for client-side requests
  :::

  :::field{name="privateAccessToken" type="string"}
  Private access token for server-side requests, also used during server-side rendering and by the
  [Shopify routes](/essentials/storefront#shopify-routes)
  :::

  :::field{name="buyerIpHeader" type="string"}
  Request header with the buyer's IP address, which is sent to Shopify with requests that use the private access token -
  default: `x-real-ip` on Vercel, `x-nf-client-connection-ip` on Netlify, `cf-connecting-ip` on Cloudflare and the
  socket address elsewhere. Behind your own reverse proxy, set the header that the proxy sets. Never use a header that
  the browser can send itself, such as `X-Forwarded-For`
  :::

  :::field{name="mock" type="boolean"}
  Use mock.shop instead of your actual store - default: `false`
  :::

  :::field{name="proxy" type="boolean"}
  Send requests from the browser through the [Storefront API proxy](/essentials/storefront#the-storefront-api-proxy)
  on your own domain - default: `true`. Statically generated sites, built with `nuxt generate` or a static preset such as
  `github_pages`, always send their requests directly to Shopify
  :::

  :::field{name="explorer" type="boolean"}
  Enable the dev-only GraphQL explorer for the client - default: `true`
  :::

  :::field{name="codegen" type="object | boolean"}
  Code generation for the client. Set to `false` to disable it - default: `true`
  :::

  :::field{name="codegen.globalTypes" type="boolean"}
  Declare this client's operation and fragment types globally - default: `true`
  :::

  :::field{name="codegen.plugins.typescript" type="object"}
  Custom TypeScript plugin options for code generation
  :::

  :::field{name="cache" type="object | boolean"}
  Default cache configuration for the client
  :::

  :::field{name="cache.browser" type="object | boolean"}
  In-memory cache for requests in the browser. Takes `max` (number of entries), `maxSize` and `maxEntrySize` (bytes)
  and `ttl` (seconds) - default: up to 1000 entries for 10 seconds
  :::

  :::field{name="cache.server" type="object | string | boolean"}
  Cache configuration for requests during server-side rendering. Takes the options of a storage mount, the name of a
  Nitro storage mount, or `false` - default: `lru-cache` driver
  :::

  :::field{name="cache.presets" type="object"}
  Named cache options to use in your application, with `maxAge`, `staleWhileRevalidate` and `staleIfError` - default:
  `short` and `long`, the same as Hydrogen's `Cache.short()` and `Cache.long()`
  :::

  :::field{name="headers" type="object"}
  Additional headers to include in requests. Part of the public runtime config, never add credentials here. When sent
  from the browser, the [Storefront API proxy](/essentials/storefront#the-storefront-api-proxy) doesn't forward them to
  Shopify.
  :::

  :::field{name="documents" type="array"}
  Glob patterns to include in [code generation](/going-further/codegen). Setting this replaces the default glob patterns for the client. An empty array falls back to the defaults. `node_modules`, `dist`, `.nuxt` and `.output` folders and `.d.ts` files are always skipped.
  :::

  :::field{name="retries" type="number"}
  Number of retries for failed requests, between `0` and `3` - default: `0`
  :::
::

#### Customer Account Client

::field-group
  :::field{name="apiVersion" type="string"}
  Shopify [API version](https://shopify.dev/docs/api/usage/versioning) to use (e.g., `2026-10`) - default: the API
  version of the installed `@shopify/hydrogen`
  :::

  :::field{name="clientId" type="string" required}
  Client ID for customer account API requests
  :::

  :::field{name="afterLogin" type="string"}
  Where to send the customer after login, unless the login was started with a `returnTo` path. After a failed login,
  the customer is sent here with a `login=failed` query parameter. Not to be confused with the OAuth callback, which is
  always `/account/authorize` - default: `/`
  :::

  :::field{name="afterLogout" type="string"}
  Where to send the customer after logout, unless the logout was started with a `returnTo` path. Must be a registered
  logout URI in your Shopify app - default: `/`
  :::

  :::field{name="session.password" type="string"}
  Password used to encrypt the session cookie (at least 32 characters). Auto-generated in development, required in
  production - server-side only
  :::

  :::field{name="session.name" type="string"}
  Name of the session cookie - default: `__Host-session`. The cookie is always `Secure`, so it only works over HTTPS,
  also in development
  :::

  :::field{name="session.maxAge" type="number"}
  Lifetime of the session cookie in seconds - default: `604800` (7 days)
  :::

  :::field{name="session.cookie.sameSite" type="'lax' | 'none'"}
  `SameSite` attribute of the session cookie - default: `lax`. `strict` is not supported, because the login fails when
  the browser doesn't send the cookie after Shopify's redirect. Setting `none` sends the cookie with requests from other
  sites, so only use it if you need cross-site embedding
  :::

  :::field{name="tokenStorage" type="string | object | boolean"}
  Where the customer's tokens are kept. By default they live in a sealed session cookie, which is stateless and works on serverless hosts. Set an [unstorage](https://unstorage.unjs.io) mount or driver (e.g. Redis) to store them server-side instead, or `true` for an in-memory store of up to 10,000 sessions (single instance only) - default: `false` (the tokens are kept in the session cookie)
  :::

  :::field{name="proxy" type="boolean"}
  Send requests from the browser through the
  [customer account proxy](/essentials/customer-account#the-customer-account-proxy) on your own domain - default:
  `true`. Statically generated sites have no server for the proxy and the `/account/*` routes, so customers can't log in
  there
  :::

  :::field{name="explorer" type="boolean"}
  Enable the dev-only GraphQL explorer for the client - default: `true`
  :::

  :::field{name="codegen" type="object | boolean"}
  Code generation for the client. Set to `false` to disable it - default: `true`
  :::

  :::field{name="codegen.globalTypes" type="boolean"}
  Declare this client's operation and fragment types globally - default: `false`
  :::

  :::field{name="codegen.plugins.typescript" type="object"}
  Custom TypeScript plugin options for code generation
  :::

  :::field{name="headers" type="object"}
  Additional headers to include in requests. Part of the public runtime config, never add credentials here. When sent
  from the browser, the [customer account proxy](/essentials/customer-account#the-customer-account-proxy) doesn't
  forward them to Shopify.
  :::

  :::field{name="documents" type="array"}
  Glob patterns to include in [code generation](/going-further/codegen). Setting this replaces the default glob patterns for the client. An empty array falls back to the defaults. `node_modules`, `dist`, `.nuxt` and `.output` folders and `.d.ts` files are always skipped.
  :::

  :::field{name="retries" type="number"}
  Number of retries for failed requests, between `0` and `3` - default: `0`
  :::
::

### GraphQL

::field-group
  :::field{name="graphql.generateConfig" type="boolean"}
  Generate a [`graphql.config.mjs`](/getting-started/editor) for IDE features like autocompletion and validation -
  default: `true`
  :::

  :::field{name="graphql.injectFragments" type="boolean"}
  Inject every [fragment](/getting-started/usage#fragments) an operation references into that operation at build
  time, so they don't have to be imported by hand. Only fragments from the `fragments.dirs` directories are injected -
  default: `true`
  :::

  :::field{name="graphql.normalize" type="boolean"}
  Strip duplicate and unused fragment definitions from an operation before it is sent to Shopify - default: `true`
  :::

### Webhooks

::field-group
:::field{name="webhooks.secret" type="string"}
Your Shopify App Client Secret. Used for HMAC validation - default: the admin client's `clientSecret`

:::field{name="webhooks.subscriptions" type="array"}

### Analytics

Set `analytics` to `true` to enable [Shopify analytics](/essentials/analytics) with the defaults, or to an object to
configure it. All options are optional - default: `false`.
The shop and market of the events come from the `shopId`, `storefrontId` and `defaultMarket` options, see [basic options](#basic-options).

::field-group
  :::field{name="analytics.autoPageView" type="boolean"}
  Report a `page_viewed` event on the initial load and on every client-side navigation - default: `true`
  :::

  :::field{name="analytics.consent.mode" type="'no-banner' | 'default-banner' | 'custom-banner'"}
  How the visitor's [consent](/essentials/analytics#consent) is collected - default: `no-banner`
  :::
::

## Complete Example

Full configuration example with all options:

```ts [nuxt.config.ts]
import { gql } from "@shopify/hydrogen"

export default defineNuxtConfig({
  modules: ["@nuxtjs/shopify"],

  shopify: {
    name: "nuxt-module-store",

    origin: "https://shop.example.com",

    shopId: "12345",
    storefrontId: "...",

    defaultMarket: {
      country: "DE",
      language: "EN",
      currency: "EUR",
    },

    routeTemplates: {
      product: "/product/:productHandle",
    },

    cart: {
      fragment: gql(`
        fragment CartFragment on Cart {
          metafields(identifiers: [{ namespace: "custom", key: "gift_message" }]) {
            key
            value
          }
        }
      `),
    },

    predictiveSearch: {
      limit: 5,
      limitScope: "EACH",
      types: ["PRODUCT", "COLLECTION", "QUERY"],
      searchableFields: ["TITLE", "VENDOR"],
      unavailableProducts: "HIDE",
    },

    clients: {
      storefront: {
        apiVersion: "2026-10",
        publicAccessToken: "...",
        privateAccessToken: "...",
        buyerIpHeader: "x-real-ip",
        mock: false,
        proxy: true,
        explorer: true,
        codegen: {
          globalTypes: true,
          plugins: {
            typescript: {},
          },
        },
        cache: {
          browser: {
            ttl: 10,
          },
          server: {
            driver: "lru-cache",
          },
          presets: {
            short: { maxAge: 1, staleWhileRevalidate: 9 },
            long: { maxAge: 3600, staleWhileRevalidate: 82800 },
          },
        },
        headers: {},
        retries: 0,
      },

      customerAccount: {
        apiVersion: "2026-10",
        clientId: "...",
        afterLogin: "/",
        afterLogout: "/",
        session: {
          name: "__Host-session",
          password: "...",
          maxAge: 604800,
          cookie: {
            sameSite: "lax",
          },
        },
        tokenStorage: false,
        proxy: true,
        explorer: true,
        codegen: {
          plugins: {
            typescript: {},
          },
        },
        headers: {},
        retries: 0,
      },

      admin: {
        apiVersion: "2026-10",
        clientId: "...",
        clientSecret: "...",
        accessToken: "...",
        refreshToken: "...",
        tokenStorage: {
          driver: "memory" 
        },
        explorer: true,
        codegen: {
          plugins: {
            typescript: {},
          },
        },
        headers: {},
        retries: 0,
      },
    },

    logger: {},

    fragments: {
      dirs: ["graphql"],
      autoImport: true,
    },

    graphql: {
      generateConfig: true,
      injectFragments: true,
      normalize: true,
    },

    errors: {
      throw: true,
    },

    webhooks: {
      secret: "...",
      subscriptions: [
        {
          topic: "ORDERS_CREATE",
          uri: "https://your-app.com/api/webhooks/orders-create",
          format: "JSON",
          filter: "",
          includeFields: ["id", "title"],
          metafieldNamespaces: [],
          metafields: [],
        },
      ],
    },

    analytics: {
      autoPageView: true,
      consent: {
```
