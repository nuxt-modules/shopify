Shopify collects analytics for headless storefronts the same way it does for themes, powering the reports and live view
in your admin. This module wires that up for you: drop-in components and a composable cover product, collection, search,
and cart views, add-to-cart, and consent.

Under the hood it loads Shopify's own analytics scripts from [`@shopify/hydrogen`](https://www.npmjs.com/package/@shopify/hydrogen),
the same ones Hydrogen storefronts use. Those scripts create an event bus on the page, handle consent, and send events to
Shopify, so you get the exact payloads Shopify expects without reimplementing them.

::note
Analytics uses functionality from `@shopify/hydrogen` (`2026.10.0` or newer). Install it before enabling analytics in the module:

```bash [Terminal]
npm install @shopify/hydrogen
```
::

## Getting started

Analytics is opt-in. Once `@shopify/hydrogen` is installed, enable it in your `nuxt.config.ts` and set your shop ID:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    name: 'nuxt-module-store',

    clients: {
      storefront: {
        publicAccessToken: '...',
      },
    },

    analytics: {
      shopId: '1234567890',
    },
  },
})
```

The shop ID is required. Without it, analytics is disabled and the module logs an error.

::note
To find your shop ID, look at your Customer Account API endpoints in the Shopify admin:

1. In the Shopify admin, open the **Headless** app.
2. Under **Customer Account API**, click **Manage**.
3. Scroll down to **Application endpoints**.
4. Find the **Authorization** endpoint. The shop ID is the number in the middle of the URL, right after `/authentication/`.

For example, if the endpoint is `https://shopify.com/authentication/1234567890/oauth/authorize`, your shop ID is
`1234567890`. You do not need to use the Customer Account API to use analytics.
::

Use the number on its own, as in `shopId: '1234567890'`. A Shop GID such as `gid://shopify/Shop/1234567890` is accepted
too. It is the same ID the Customer Account API calls `SHOP_ID`.

The shop ID is not a secret, so writing it in the config is fine. To read it from an environment variable instead,
declare the key with an empty placeholder under `runtimeConfig` so Nuxt can override it:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    shopify: {
      analytics: {
        shopId: '', // set NUXT_SHOPIFY_ANALYTICS_SHOP_ID
      },
    },
  },
})
```

## Configuration

The `analytics` option accepts `true`, `false` (default), or an object with the following settings. `shopId` is
required; the rest are optional:

::field-group
  :::field{name="shopId" type="string"}
  Your numeric shop ID, or a Shop GID. Required.
  :::

  :::field{name="country" type="string"}
  Two-letter country code (e.g. `CA`) of the default market. Defaults to `US`.
  :::

  :::field{name="language" type="string"}
  Language code (e.g. `EN`) of the default market. Defaults to `EN`.
  :::

  :::field{name="currency" type="string"}
  Currency code (e.g. `USD`). Used for prices that do not carry their own currency, such as the product in
  `ShopifyProductView`.
  :::

  :::field{name="storefrontId" type="string"}
  Storefront ID from your Headless sales channel. It is passed to Shopify's performance script. Events are reported on
  the Headless sales channel, which does not attribute them to a storefront ID.
  :::

  :::field{name="consent" type="object"}
  Customer Privacy (consent) options, see [Consent](#consent) below.
  :::
::

## Tracking views

Page views are automatic, there is no component to place. Shopify's scripts report one `page_viewed` event on the
initial load and on every client-side navigation.

Views that Shopify understands (product, collection, search, cart) have a renderless component each. The product,
collection, and search components also re-report when the item they describe changes (the product, the collection,
or the search term), which covers client-side navigation between two products. `ShopifyCartView` reports once per mount.

```vue [~/app/pages/products/[handle].vue]
<template>
  <!-- your product page -->

  <ShopifyProductView
    :data="{
      products: [{
        id: product.id,
        title: product.title,
        vendor: product.vendor,
        price: product.selectedOrFirstAvailableVariant.price.amount,
        currencyCode: product.selectedOrFirstAvailableVariant.price.currencyCode,
        variantId: product.selectedOrFirstAvailableVariant.id,
        variantTitle: product.selectedOrFirstAvailableVariant.title,
      }],
    }"
  />
</template>
```

Each product needs `id`, `title`, `price`, `vendor`, `variantId`, and `variantTitle`, otherwise Shopify drops the
event and the module logs which field is missing. `currencyCode` is optional. When it is missing, the module uses
`analytics.currency`, then the currency Shopify set on the page.

The other view components follow the same shape:

```vue
<template>
  <ShopifyCollectionView :data="{ collection: { id: collection.id, handle: collection.handle } }" />

  <ShopifySearchView :data="{ searchTerm: query }" />

  <ShopifyCartView :data="{ cart }" />
</template>
```

::warning
`ShopifyCustomView` is no longer supported. Shopify's event bus ignores custom event names, so custom events reach
neither Shopify nor your subscribers.
::

## Analytics composable

To publish events manually, use the `useShopifyAnalytics()` composable. It is safe to call anywhere, including on the server.
When analytics is disabled, it returns a no-op.

```ts
const analytics = useShopifyAnalytics()

analytics.publish('product_viewed', {
  products: [/* ... */]
})

const off = analytics.subscribe('product_viewed', (payload) => {
  // payload is typed to the event
})

analytics.canTrack() // whether the visitor consented to analytics
```

`publish` takes the same shapes as the components. `subscribe` receives the payload exactly as it was put on Shopify's
event bus (for example a product's `price` is `{ amount, currencyCode }`), and it only fires once consent allows
tracking. The `analytics:publish` [hook](/going-further/hooks) fires for the same events.

### Cart events

Cart events are derived, so you never publish them yourself. Keep the cart in sync after every change and Shopify's cart
tracking works out what changed by comparing the previous cart with the new one:

```ts
const analytics = useShopifyAnalytics()

const { data } = await addToCartMutation()

analytics.setCart({
  ...data.cart,
  lines: flattenConnection(data.cart.lines),
})
```

That publishes `cart_updated`, plus a `product_added_to_cart` or `product_removed_from_cart` for every line whose
quantity changed. Only `product_added_to_cart` reaches Shopify; the other two are for your own subscribers.

The cart needs `id` and `updatedAt`, and each line needs `merchandise.product.id` and `merchandise.product.vendor`, or
the event cannot be attributed. A line's currency comes from the line price, then the cart total, then
`analytics.currency`. Updates carrying an `updatedAt` that was already reported are ignored, so a reload never
re-reports a cart.

Call `setCart` from the one place every cart change passes through, such as a plugin that watches your cart store,
rather than from a component. A cart drawer is often unmounted when an item is added from a product page, and the add
would be missed.

```ts [~/app/plugins/shopify-analytics.client.ts]
export default defineNuxtPlugin(() => {
  const cartStore = useCartStore()
  const analytics = useShopifyAnalytics()

  watch(
    () => cartStore.cart,
    cart => analytics.setCart(cart ? { ...cart, lines: flattenConnection(cart.lines) } : null),
    { immediate: true, deep: true },
  )
})
```

### Forwarding to other tools

Because everything runs through one bus, `subscribe` is also how you fan events out to a third-party provider such as GA4 or Meta:

```ts [~/app/plugins/ga.client.ts]
export default defineNuxtPlugin(() => {
  const analytics = useShopifyAnalytics()

  analytics.subscribe('product_added_to_cart', ({ currentLine }) => {
    gtag('event', 'add_to_cart', { /* map from currentLine */ })
  })
})
```

## Consent

Every event is gated on Shopify's [Customer Privacy API](https://shopify.dev/docs/api/customer-privacy). In regions that
require opt-in, such as the EU, nothing is sent and no tracking cookies are set until the visitor consents. Elsewhere,
Shopify's API may permit tracking by default. Either way, consent is dictated by Shopify, not the module.

Without a banner, visitors from regions that require consent are never tracked, because nothing records their consent.
To collect it, turn on Shopify's own banner:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    analytics: {
      shopId: '1234567890',
      consent: {
        banner: true,
      },
    },
  },
})
```

::field-group
  :::field{name="banner" type="boolean"}
  Load Shopify's own cookie banner. Defaults to `false`. Leave it off to build your own.
  :::
::

Shopify's scripts talk to the Storefront API through your app, so the module adds a
`POST /api/:version/graphql.json` route (for example `/api/unstable/graphql.json`) when a public storefront token is
configured. It forwards to the storefront proxy and adds the public token on the server. This needs
`clients.storefront.publicAccessToken`.

### Recording consent

Record the visitor's choice through the composable, or from your own banner:

```ts
const analytics = useShopifyAnalytics()

analytics.setTrackingConsent({
  analytics: true,
  marketing: true,
  preferences: true,
  sale_of_data: true,
})
```

`ShopifyPrivacyBanner` is a renderless component that holds `accept`, `decline`, `setConsent`, and `canTrack`
through its slot, you can style the banner however you like:

```vue
<template>
  <ShopifyPrivacyBanner v-slot="{ accept, decline }">
    <div class="banner">
      <p>We use cookies to measure our store.</p>

      <button @click="accept">
        Accept
      </button>

      <button @click="decline">
        Decline
      </button>
    </div>
  </ShopifyPrivacyBanner>
</template>
```

If you set `banner: true`, Shopify renders its own banner and you can skip this component entirely.

Connecting a third-party consent provider is not supported yet.

### Reopening preferences

Once a visitor has made a choice, Shopify's banner disappears.
To reopen the consent dialog on demand, use the `showPreferences()` method from the composable:

```vue
<script setup lang="ts">
const analytics = useShopifyAnalytics()
</script>

<template>
  <button @click="analytics.showPreferences()">
    Cookie Preferences
  </button>
</template>
```

The dialog is Shopify's own, so this needs `banner` to be enabled.
Shopify only renders the banner in regions where consent applies.
When using your own banner, you have to handle the state yourself.

## Upgrading

Analytics now runs on Shopify's hosted scripts from `@shopify/hydrogen` instead of `@shopify/hydrogen-react`:

- Install `@shopify/hydrogen` `2026.10.0` or newer, and remove `@shopify/hydrogen-react`.
- Set `analytics.shopId`. It is no longer looked up from the Storefront API.
- Remove `autoPageView`, `domain`, `consent.checkoutDomain`, `consent.storefrontAccessToken`, `consent.banner.country`,
  and `consent.banner.language`. Page views are always automatic and consent is configured by Shopify.
- `subscribe` and the `analytics:publish` hook now receive Shopify's payload shapes, only after consent allows
  tracking, and they include cart events and Shopify's own page views.
- `ShopifyCustomView` and custom events are not supported. `setShopContext` no longer re-resolves the market.
