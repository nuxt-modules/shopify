Shopify collects analytics for headless storefronts the same way it does for themes, powering the reports and live view
in your admin. This module wires that up for you: drop-in components and a composable cover product, collection, search,
and cart views, add-to-cart, and consent.

Under the hood it runs on the scripts Shopify's own storefronts load, shipped with
[`@shopify/hydrogen`](https://www.npmjs.com/package/@shopify/hydrogen): the analytics bus, the Customer Privacy API and
Shopify's privacy banner. You get the exact events Shopify expects without reimplementing them.

::note
Analytics needs `@shopify/hydrogen` 2026.10 or newer. Install it before enabling analytics in the module:

```bash [Terminal]
npm install @shopify/hydrogen
```
::

## Getting started

Analytics is opt-in. Once `@shopify/hydrogen` is installed, you can enable it in your `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    name: 'nuxt-module-store',

    clients: {
      storefront: {
        publicAccessToken: '...',
      },
    },

    analytics: true,
  },
})
```

## Configuration

The `analytics` option accepts `true`, `false` (default), or an object with the following settings, all optional:

::field-group
  :::field{name="storefrontId" type="string"}
  Storefront ID from your Hydrogen sales channel. Attributes events to that storefront; without it, events are
  attributed to the Headless channel.
  :::

  :::field{name="shopId" type="string"}
  Shop ID as `gid://shopify/Shop/<id>`. The automatic shop lookup is only skipped when `shopId`, `country`, `language`
  and `currency` are all set.
  :::

  :::field{name="country" type="string"}
  Country code of your default market (e.g. `US`). Resolved from the Storefront API when omitted, see
  [Buyer market](#buyer-market) for multi-market shops.
  :::

  :::field{name="language" type="string"}
  Language code of your default market (e.g. `EN`). Resolved from the Storefront API when omitted.
  :::

  :::field{name="currency" type="string"}
  Currency code of your default market (e.g. `USD`). Resolved from the Storefront API when omitted.
  :::

  :::field{name="autoPageView" type="boolean"}
  Publish a `page_viewed` event on the initial load and on every client-side navigation. Defaults to `true`; set it to
  `false` to publish page views yourself.
  :::

  :::field{name="consent" type="object"}
  How the visitor's consent is collected, see [Consent](#consent) below.
  :::
::

## Shopify's scripts

The module renders Shopify's script tags in the document head and starts them after hydration. The scripts call
Shopify through your storefront's own origin, so the module serves these paths before your routes and forwards only
Shopify's cookies (`_shopify_*`, `_tracking_consent` and `cart`) to Shopify:

- `/api/<version>/graphql.json` and `/__shopify/*`
- `/cart.js` and `/cart/{add,update,change,clear}.js`, also as `.json` and behind a locale prefix such as `/de-de`
- `/.well-known/ucp`, `/.well-known/shopify/fec/produce` and `/.well-known/apple-developer-merchantid-domain-association`
- `/api/mcp` and `/api/ucp/mcp`

Requests without a storefront access token get the storefront client's `publicAccessToken`, so they also work on a
password-protected store.

::warning
Shopify's scripts need a server for these paths. A statically generated site only reports analytics when your host
forwards them to your store.
::

## Tracking views

Page views are automatic — there is no component to place. Once Shopify's scripts are running, the module publishes a
`page_viewed` event for the landing page and for every client-side navigation. Views are keyed on path and query, so
jumping to an anchor on the same page does not report a second view.

Views that Shopify understands (product, collection, search, cart) have a renderless component each. Their `data` is
the event payload from `@shopify/hydrogen` (`ProductViewPayload`, `CollectionViewPayload`, `SearchViewPayload`). The
product, collection, and search components also re-report when the item they describe changes (the product, the
collection, or the search term), which covers client-side navigation between two products. `ShopifyCartView` reports
once per mount.

```vue [~/app/pages/products/[handle].vue]
<template>
  <!-- your product page -->

  <ShopifyProductView
    :data="{
      products: [{
        id: product.id,
        title: product.title,
        vendor: product.vendor,
        price: variant.price,
        variantId: variant.id,
        variantTitle: variant.title,
        quantity: 1,
      }],
    }"
  />
</template>
```

`price` is the variant's `MoneyV2` (`{ amount, currencyCode }`), exactly as the Storefront API returns it. The other
view components follow the same pattern:

```vue
<template>
  <ShopifyCollectionView :data="{ collection: { id: collection.id, handle: collection.handle } }" />

  <ShopifySearchView :data="{ searchTerm: query }" />

  <ShopifyCartView />
</template>
```

`ShopifyCartView` reports the cart you hand over with [`setCart`](#cart-events), or the one you pass as its `cart`
prop.

## Analytics composable

To publish events manually, use the `useShopifyAnalytics()` composable. It is safe to call anywhere, including on the
server. When analytics is disabled, it returns a no-op.

```ts
const analytics = useShopifyAnalytics()

analytics.publish('product_viewed', {
  products: [/* ... */],
})

analytics.canTrack() // whether Shopify's Customer Privacy API allows analytics
analytics.shop.value // the shop Shopify's scripts report
analytics.i18n.value // the market Shopify's scripts report
```

`publish` hands the event to Shopify's analytics bus, with the event names and payloads typed by `@shopify/hydrogen`.
Events published before Shopify's scripts start are delivered once they do. The bus only accepts Shopify's standard
events.

### Buyer market

Events carry the country, currency and language of the market they happened in. By default that is your shop's
*default* market. To report another market, call `setShopContext` with its `country` and/or `language`; the module
resolves the market with Shopify's `@inContext` directive. Call it during server rendering, so Shopify's scripts
already start in that market, and again whenever the buyer switches markets:

```ts [~/app/plugins/analytics-market.ts]
export default defineNuxtPlugin(async () => {
  const analytics = useShopifyAnalytics()

  await analytics.setShopContext({
    country: 'CA',
    language: 'FR',
  })
})
```

`country` is a Shopify `CountryCode` (`CA`, `DE`) and `language` a `LanguageCode` (`EN`, `PT_BR`). Each market is
resolved once and cached. When Shopify cannot resolve a market, the previous one stays.

### Cart events

Shopify derives the cart events (`cart_updated`, `product_added_to_cart` and `product_removed_from_cart`) itself, with
Hydrogen's `trackCartAnalytics`. Hand the module your cart after every change, in the shape the Storefront API returns
it:

```ts
const analytics = useShopifyAnalytics()

const { data } = await addToCartMutation()

analytics.setCart(data.cartLinesAdd.cart)
```

The cart needs `id`, `updatedAt` and its `lines` as `nodes`, and each line its `quantity`, `cost.amountPerQuantity`
and `merchandise`:

```graphql
fragment CartFields on Cart {
  id
  updatedAt
  cost { totalAmount { amount currencyCode } }
  lines(first: 250) {
    nodes {
      id
      quantity
      cost { amountPerQuantity { amount currencyCode } }
      merchandise {
        ... on ProductVariant {
          id
          title
          sku
          product { id title vendor productType handle }
        }
      }
    }
  }
}
```

Setting the cart during server rendering works too: the browser starts from that cart and only reports what changes
afterwards. Shopify remembers the last reported update, so a reload never reports a cart twice.

If your storefront uses Hydrogen's own cart from `@shopify/hydrogen/vue`, call its `useCartAnalytics()` instead.

### Forwarding to other tools

Add other tools such as GA4 or Meta as destinations of Shopify's analytics bus. Shopify delivers events to them only
while the visitor's consent allows it, including the events published before:

```ts [~/app/plugins/ga.client.ts]
export default defineNuxtPlugin(() => {
  const analytics = useShopifyAnalytics()

  analytics.addDestination({
    name: 'ga4',
    setup: ({ subscribe }) => subscribe('product_added_to_cart', ({ currentLine }) => {
      gtag('event', 'add_to_cart', { /* map from currentLine */ })
    }),
  })
})
```

`addDestination` returns a function that removes the destination again.

## Consent

Every event is gated on Shopify's [Customer Privacy API](https://shopify.dev/docs/api/customer-privacy). In regions
that require opt-in, such as the EU, nothing is delivered and no tracking cookies are set until the visitor consents.
Elsewhere, Shopify's API may permit tracking by default. Either way, consent is dictated by Shopify, not the module.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  shopify: {
    analytics: {
      consent: {
        mode: 'default-banner',
      },
    },
  },
})
```

::field-group
  :::field{name="mode" type="'no-banner' | 'default-banner' | 'custom-banner'"}
  `no-banner` (default) loads only the Customer Privacy API and leaves the banner to you. `default-banner` loads
  Shopify's own privacy banner. `custom-banner` holds every event until your banner or consent provider records the
  visitor's choice, also where Shopify would allow tracking by default.
  :::
::

### Recording consent

Record the visitor's choice through the composable, from your own banner or your consent provider:

```ts
const analytics = useShopifyAnalytics()

await analytics.setTrackingConsent({
  analytics: true,
  marketing: true,
  preferences: true,
  sale_of_data: true,
})
```

The promise resolves once Shopify stored the choice and rejects when it could not. With `custom-banner`, the first
recorded choice releases the events, so pass your consent provider's saved choice on every page load as well.

`ShopifyPrivacyBanner` is a renderless component that holds `accept`, `decline`, `setConsent`, `canTrack` and
`shouldShowBanner` through its slot, so you can style the banner however you like. `shouldShowBanner()` tells you
whether Shopify asks for a banner for the current visitor:

```vue
<template>
  <ShopifyPrivacyBanner v-slot="{ accept, decline, shouldShowBanner }">
    <div
      v-if="shouldShowBanner()"
      class="banner"
    >
      <p>We use cookies to measure our store.</p>

      <button @click="accept">
        Accept
      </button>

      <button @click="decline">
        Decline
      </button>
    </div>
  </ShopifyPrivacyBanner>
</template>
```

With `mode: 'default-banner'`, Shopify renders its own banner and you can skip this component entirely.

### Reopening preferences

Once a visitor has made a choice, Shopify's banner disappears.
To reopen the consent dialog on demand, use the `showPreferences()` method from the composable:

```vue
<script setup lang="ts">
const analytics = useShopifyAnalytics()
</script>

<template>
  <button @click="analytics.showPreferences()">
    Cookie Preferences
  </button>
</template>
```

The dialog is Shopify's own, so this needs `mode: 'default-banner'`.
It waits for the banner script to load before opening and Shopify only renders the banner in regions where consent applies.
When using your own banner, you have to handle the state yourself.
